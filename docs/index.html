Overview

Mobile operating systems forcefully terminate background applications due to memory pressure (OOM) or system reboots without guaranteeing final shutdown callbacks.

react-native-journey-recovery solves this by establishing an explicit, safe, and verifiable checkpointing lifecycle. When your users are filling out a KYC verification, multi-screen checkout, or onboarding wizard, they will never lose progress.

🔒

Atomic & Mutex-Protected

Per-journey promise queue serializes high-frequency saves, eliminating write races. A failed save never destroys the prior committed snapshot.

🛡️

Tamper & Corruption Proof

Deterministic FNV-1a checksums detect storage corruption or manual tampering before any restoration occurs.

🔄

Schema Migrations

Ship app updates with confidence. Older snapshot schemas are safely upgraded on restore via custom migration handlers.

⏳

TTL Expiry Policies

Configurable time-to-live policies prevent stale, obsolete sessions from lingering or auto-restoring after deadlines.

Why Journey Recovery vs Simple Persistence?

Most apps attempt session persistence by auto-serializing their entire global Redux or Zustand store. This creates critical security risks, large storage bloat, stale backend assumptions, and fragile restore bugs.

Capability Standard Key-Value Persistence react-native-journey-recovery
Scope Global store dump (entire state tree) Selective journey checkpoints (explicit fields only)
Concurrent Writes Last-write-wins (silent data races) Serialized Promise Mutex Queue
Write Failure Safety Corrupts key if write is interrupted Atomic preservation of prior checkpoint
Corruption Detection Syntax errors only Deterministic FNV-1a Checksum
Schema Evolution Breaks app on version change Built-in migrate() handler
Expiration Policy None (persists indefinitely) Configurable TTL with status distinction
Server Cache Sync Assumes saved UI is backend truth TanStack Query cache revalidation

Installation

Install react-native-journey-recovery along with your preferred persistent storage adapter:

Bash 
# npm
npm install react-native-journey-recovery @react-native-async-storage/async-storage

# yarn
yarn add react-native-journey-recovery @react-native-async-storage/async-storage

# pnpm
pnpm add react-native-journey-recovery @react-native-async-storage/async-storage

# Expo
npx expo install react-native-journey-recovery @react-native-async-storage/async-storage
💡 Pure TypeScript Engine
react-native-journey-recovery contains zero native Swift or Kotlin code. It runs seamlessly in both Bare React Native and Expo (Go & Prebuild) without requiring custom native compilation.

Quickstart (3 Steps)

Step 1: Wrap App with RecoveryProvider

Initialize the recovery provider at the root of your application:

TSX 
import React from 'react';
import AsyncStorage from '@react-native-async-storage/async-storage';
import { RecoveryProvider, AsyncStorageAdapter } from 'react-native-journey-recovery';
import { AppNavigator } from './AppNavigator';

const storage = new AsyncStorageAdapter(AsyncStorage);

export default function App() {
  return (
    <RecoveryProvider storage={storage} options={{ defaultExpiry: 24 * 60 * 60 * 1000 }}>
      <AppNavigator />
    </RecoveryProvider>
  );
}

Step 2: Checkpoint Journey Progress

In your multi-step screen or wizard, register the journey and save checkpoints at each step:

TSX 
import { useJourney } from 'react-native-journey-recovery';

export function CheckoutScreen({ currentStep, cartData }) {
  const journey = useJourney('checkout-flow', {
    version: 1,
    autoSave: true,
    debounceMs: 500,
  });

  const onNextStep = async (nextStepData) => {
    // Automatically saved with mutex protection and checksum
    await journey.checkpoint({
      step: currentStep + 1,
      ...nextStepData,
    }, {
      exclude: ['creditCardNumber', 'cvv'], // Exclude sensitive fields
    });
  };

  // ...
}

Step 3: Restore or Offer Recovery

On next launch, inspect available checkpoints with useRecovery or RecoveryBanner:

TSX 
import { useRecovery, RecoveryBanner } from 'react-native-journey-recovery';

export function HomeScreen({ navigation }) {
  return (
    <View style={{ flex: 1 }}>
      <RecoveryBanner
        journeyId="checkout-flow"
        title="Resume unfinished checkout?"
        onRestored={(savedData) => {
          navigation.navigate('Checkout', savedData);
        }}
      />
      {/* Rest of your Home UI */}
    </View>
  );
}

Write Serialization & Mutex Queue

When forms auto-save on rapid keystrokes, storage writes can resolve out of order. CheckpointManager maintains an internal per-journey Promise FIFO queue:

TypeScript Concept 
// User types "A", then "AB", then "ABC" within 50ms:
// Write 1 ("A")   ---> Enqueued
// Write 2 ("AB")  ---> Waits for Write 1
// Write 3 ("ABC") ---> Waits for Write 2
// Guaranteed: Write 3 commits last. Zero race conditions.

Storage Adapters

Swap storage backends without altering your application or hook logic:

1. MMKV Storage Adapter (High Performance)

TypeScript 
import { MMKV } from 'react-native-mmkv';
import { MMKVStorageAdapter, RecoveryProvider } from 'react-native-journey-recovery';

const mmkv = new MMKV({ id: 'journey-recovery-storage' });
const storage = new MMKVStorageAdapter(mmkv);

<RecoveryProvider storage={storage}> ... </RecoveryProvider>

2. Custom Storage Adapter

Implement the simple StorageAdapter interface to connect any encrypted database (e.g. SQLite, WatermelonDB, Realm):

TypeScript 
import { StorageAdapter } from 'react-native-journey-recovery';

export class EncryptedSecureStorageAdapter implements StorageAdapter {
  async getItem(key: string): Promise<string | null> {
    return mySecureDB.get(key);
  }
  async setItem(key: string, value: string): Promise<void> {
    await mySecureDB.set(key, value);
  }
  async removeItem(key: string): Promise<void> {
    await mySecureDB.delete(key);
  }
}

Form & State Integrations

React Hook Form (`useJourneyForm`)

Automatically subscribes to form.watch() and resets form on restore:

TSX 
import { useForm } from 'react-hook-form';
import { useJourneyForm } from 'react-native-journey-recovery';

export function RegistrationForm() {
  const form = useForm<RegisterData>();
  const { hasSavedProgress, restoreToForm, clearForm } = useJourneyForm('register', form, {
    autoSave: true,
    exclude: ['password'],
  });

  return (
    <View>
      {hasSavedProgress && <Button title="Resume Application" onPress={restoreToForm} />}
      {/* Form Inputs */}
    </View>
  );
}

Formik (`useJourneyFormik`)

Connects seamlessly with any Formik instance:

TSX 
import { useFormik } from 'formik';
import { useJourneyFormik } from 'react-native-journey-recovery';

const formik = useFormik({
  initialValues: { email: '', address: '' },
  onSubmit: (values) => submit(values),
});

const { hasSavedProgress, restoreToFormik } = useJourneyFormik('profile-flow', formik);

TanStack Query Coordination (`useJourneyQuery`)

Restores local client inputs while invalidating or refetching server-owned cache (e.g. flight pricing, seat availability, cart stock):

TSX 
import { useJourneyQuery } from 'react-native-journey-recovery';

const { available, restoreAndRevalidate } = useJourneyQuery('flight-booking', {
  queryClient,
  invalidateOnRestore: [['flight-pricing'], ['seat-map', flightId]],
  refetchOnRestore: [['user-balance']],
  onRevalidated: (restoredData) => {
    console.log('Restored with fresh real-time server prices:', restoredData);
  },
});

Zod Schema Validation

Validate snapshots before restoration with Zod to guarantee strict runtime type safety:

TypeScript 
import { z } from 'zod';
import { useJourney, createZodValidator } from 'react-native-journey-recovery';

const KYCStepSchema = z.object({
  fullName: z.string().min(2),
  nationalId: z.string().length(10),
  step: z.number().int().min(1).max(5),
});

type KYCStepData = z.infer<typeof KYCStepSchema>;

export function KYCFlow() {
  const journey = useJourney<KYCStepData>('kyc-verification', {
    version: 1,
    validate: createZodValidator(KYCStepSchema), // Rejects corrupted or malformed data
  });
}
